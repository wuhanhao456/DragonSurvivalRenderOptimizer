# 无效和实验运行

- 最初 NPC 场景的测试相机被整包/DS 的钩子覆盖，未拍到模型，驱动报告 `No GPU drawing in scene mo-4`。该轮不加入性能比较。测试驱动增加最终相机校正；后续基线和候选均使用同一个冻结驱动。
- 同帧动画复用实验在 Unbound（默认 `shadowEntities=false`）的末/地黄龙短测中没有命中：末 4560 次未命中、地黄龙 5612 次未命中。没有证据表明它能改善本场景，移入 `experiments/frame-animations`，不在客户端 jar、默认配置或 Mixins 中。
- 第一次 12 玩家 alpha.4 基线实例在读取世界数据阶段发生 `OutOfMemoryError: Java heap space`，堆上限 8 GiB。尚未开始场景采样，驱动结果为失败、场景数为零。该次启动作废，保持相同配置重试；没有提高堆上限或把启动失败记成优化收益。重试正常进入场景。
- 首个 NPC 视觉驱动执行了无光影及八个光影包的 CPU/GPU 阶段，但在行走动作断言处失败。驱动在客户端实体上调用 Core 的 `setState`/`setEmote`；这些方法明确在客户端直接返回，因此动作没有被设置。这不是有效的行走验证。改为创建真实服务端 NPC，调用原服务端方法，通过原同步更新客户端，再检查控制器与姿态。第一次运行的失败结果和 19 个已完成阶段保留。
- 最终 jar 的一次 Core 版本不匹配实例在启动期发生 JVM `EXCEPTION_ACCESS_VIOLATION`，线程为 `C2 CompilerThread0`，正在编译 `org.objectweb.asm.ClassReader::readCode`。兼容日志已确认 `GPU=true; NPC=unsupported Core version 0.10.2`，但还未进入世界，未产生场景结果。该次不作为兼容通过或性能数据；相同 Java/堆/参数重试后完成世界检查，DS GPU 保持启用、NPC GPU 为零、清理为零。原 `hs_err`/replay 文件留在私有隔离目录，不上传启动参数。
- 最终 NPC 视觉实例 `...-023558` 完成 28 项截图与断言：无光影、八个光影 CPU/GPU、六种真实服务端动作、NPC 开关、重载、物品栏和模式切换。随后驱动直接调用 `Minecraft.disconnect(Screen)`，漏掉正常退出的 `ClientLevel.disconnect()`，本地服务器没有收到连接关闭通知，渲染线程等待其停止。该实例被明确识别后终止；原 28 项记录保留，但没有伪造总体通过或退出清理结果。修正测试驱动，单独复核资源重载、开关、模式与退出，不重复性能采样。
