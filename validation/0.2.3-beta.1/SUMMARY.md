# DSRO 0.2.3-beta.1 验证

测试版。测得客户端 SHA-256：`c865cb328db1a61b4664231b8eb284877d8dcd86ebd306edda74f2ddef0acc1b`，五次游戏内运行使用同一个 jar。

## 改动依据

0.2.1 短测中，默认 GPU 模式下的姿态捕获（GeckoLib 骨骼遍历与捕获）约占渲染线程 CPU 的一半。DS 2.0.71 的发光层和盔甲层以 `isReRender=true` 在同一帧再次调用 `actuallyRender`，因此每条龙、每个龙魂每帧要遍历三遍骨骼树，后两遍得到相同的矩阵。0.2.3-beta.1 让这两次重渲染复用基础通道的骨骼矩阵：只在根矩阵、每根骨骼的变换与隐藏标志都逐位相同时复用，否则照常遍历。

由于同一模型的骨骼对象被所有龙共享，以下任一情况发生时不复用：基础通道期间有其他实体渲染了同一模型（A→B→A 嵌套），或模型在两次渲染之间被其他实体使用过（包括 DS 只计算骨骼的调用）。另外，基础通道开始和结束时读到的骨骼状态必须一致，模板计入网格预算。

## 方法与硬件

- 本机 AMD EPYC 7F52、NVIDIA RTX 5060 Ti、驱动 610.88，Windows Server 2025。
- 与 0.2.1 相同的冻结整包、场景和固定镜头：1280×720、视距 6、VSync 关闭。
- 场景为低端支持关闭（即默认 GPU 模式）的 1 玩家、12 玩家（三种模型）、17 龙魂 + 4 末 + 4 地黄龙，每景预热 15 秒、采样 60 秒，每组一次。
- 对照组为 `--stage 4`（关闭复用），候选组为 `--stage 5`（发布默认），两组用同一 jar、同一驱动。
- 无光影与 Complementary Unbound r5.9 各一组。
- 平均 FPS 与 1% Low 均不得退步超过 5%。

工具：`tools/run_rerender_pair.py`，原始结果见 [rerender/](rerender)。

## 其他检查

- 34 项 Java 单元测试通过，新增重渲染复用的命中、各类未命中、A→B→A 嵌套、基础通道中骨骼变化，以及预算与生命周期等用例。契约测试还会在 `GeoRenderer.actuallyRender` 中插入一个额外调用，确认复用随之关闭。
- OpenGL 检查（[gl-results.json](gl-results.json)）新增 `rerenderPoseReuseMatchesFreshCapture`：复用快照经计算着色器的输出，与重新捕获的输出逐字节一致，GL error 为 0。

## 范围

- 每组只跑一次，为本机短测，不代表其他硬件，也不替代三轮正式 Low 验收。
- 没有重新运行 0.2.1 的完整功能覆盖（物品栏、编辑器、资源重载、断线等）。复用只作用于世界渲染，GUI 预览本来就走 CPU，不受影响。
- 固定镜头场景中没有实测"同模型嵌套渲染"的整包情况，这一路径由单元测试覆盖。
- 若其他模组在重渲染的骨骼遍历中注入了逐骨逻辑，可在配置中关闭 `reuseRerenderPoses`。
